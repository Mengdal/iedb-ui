# 集群管理

IEDB 集群支持多节点部署，实现读写分离、自动故障转移和高可用。集群通过 Raft 共识协议协调节点，支持共享存储（S3/MinIO/Azure）和本地存储两种模式。

## OSS vs Enterprise

| 能力 | OSS | Enterprise |
|---|---|---|
| **部署与扩展** | | |
| 单节点部署 | ✅ | ✅ |
| 多节点集群 | - | ✅ |
| 角色分离（writer / reader / compactor） | - | ✅ |
| 自动故障转移（writer + compactor） | - | ✅ |
| 共享存储（S3 / MinIO / Azure） | ✅ | ✅ |
| 本地存储 + 节点间复制 | - | ✅ |
| 心跳健康检测 | - | ✅ |
| **安全** | | |
| Token 认证 | ✅ | ✅ |
| 组织/团队/RBAC | - | ✅ |
| Measurement 级权限 | - | ✅ |
| 集群 TLS + 共享密钥 | - | ✅ |
| 审计日志 | - | ✅ |
| **数据生命周期** | | |
| 连续查询（手动执行） | ✅ | ✅ |
| 保留策略（手动执行） | ✅ | ✅ |
| 自动调度（CQ + 保留策略） | - | ✅ |
| 分层存储（热/冷） | - | ✅ |
| 备份恢复 | - | ✅ |
| **可观测性** | | |
| Prometheus 指标 | ✅ | ✅ |
| 查询治理（速率限制/配额） | - | ✅ |
| 活跃查询管理 | - | ✅ |

## 快速开始

集群功能需要企业许可证。将许可证密钥添加到配置文件中：

```toml
# iedb.toml
[license]
key = "IEDB-XXXX-XXXX-XXXX-XXXX"
```

或通过环境变量：

```bash
export IEDB_LICENSE_KEY="IEDB-XXXX-XXXX-XXXX-XXXX"
```

> 从 OSS 升级到 Enterprise 无需数据迁移——添加许可证密钥，启用所需功能，重启即可。

## 架构概览

================================================================================
                    IotEdgeDB Cluster Architecture Overview
================================================================================

+============================================================================+
|                           Client Layer                                     |
|   HTTP API (Fiber) ---- Line Protocol / MsgPack / TLE / SQL                |
+=============+==========================================+===================+
              |                                          |
       +------v------+                          +--------v--------+
       | Write Path  |                          |  Query Path     |
       +------+------+                          +--------+--------+
              |                                          |
+=============v==========================================v===================+
|                         Router Layer                                       |
|                                                                            |
|   RouteWrite() -> ShardRouter -> Primary Writer                            |
|   RouteQuery() -> ShardRouter -> Reader / Replica                          |
|   ScatterGather -> parallel fan-out to multi-shard                         |
+=============+==========================================+===================+
              |                                          |
+=============v==========================================v===================+
|                       Coordinator Layer                                    |
|                                                                            |
|   +----------------------------------------------------------------+       |
|   |  Raft Consensus (Hashicorp Raft + BoltDB)                      |       |
|   |  FSM: Node Registry + File Manifest + Writer/Compactor Lease   |       |
|   +----------------------------------------------------------------+       |
|                                                                            |
|   +----------------+  +----------------+  +----------------+               |
|   | Writer         |  | Reader         |  | Compactor      |               |
|   |  - Primary     |  |  - Read-only   |  |  - Parquet     |               |
|   |  - Standby     |  |  - WAL recv    |  |    compaction  |               |
|   +-------+--------+  +-------+--------+  |  - Lease mgmt  |               |
|           |                    |           +-------+--------+              |
+===========v====================v===================v=======================+
              |                    |                   |
+=============v====================v===================v======================+
|                     Replication Layer (3 Phases)                            |
|                                                                             |
|   Phase 1: WAL Stream         (Writer -> Reader, real-time)                 |
|   Phase 2: Parquet P2P        (SHA-256 + resume, peer-to-peer)              |
|   Phase 3: Startup Catch-up   (Manifest reconciliation + pull)              |
+=============+====================+===================+======================+
              |                    |                   |
+=============v====================v===================v======================+
|                       Storage Layer                                         |
|                                                                             |
|   Local Disk / S3 / MinIO / Azure Blob                                      |
|   Parquet Files + Arrow In-Memory Buffer                                    |
+=============================================================================+

```

### 节点角色

| 角色 | 写入 | 查询 | 压缩 | Raft 投票 |
|---|---|---|---|---|
| `writer` | ✅ | ✅ | - | ✅ |
| `reader` | - | ✅ | - | - |
| `compactor` | - | - | ✅ | - |
| `standalone` | ✅ | ✅ | ✅ | - |

**Writer 子状态：**
- `primary` — 当前活跃主节点，处理所有写入
- `standby` — 热备节点，随时可接管

## 集群搭建

### 共享存储模式（推荐）

所有节点共享同一个对象存储（S3/MinIO/Azure），Writer 写入 Parquet 文件后，Reader 通过 DuckDB `httpfs` 扩展直接读取。

#### 第一步：配置并启动首个 Writer 节点（Bootstrap）

```toml
# writer-01.toml
[license]
key = "IEDB-XXXX-XXXX-XXXX-XXXX"

[server]
port = 8000

[storage]
backend = "s3"
s3_bucket = "iedb-production"
s3_region = "us-east-1"

[cluster]
enabled = true
node_id = "writer-01"
role = "writer"
cluster_name = "production"
raft_bootstrap = true               # 仅首个节点
raft_data_dir = "./data/raft"
coordinator_addr = ":9100"
raft_bind_addr = ":9200"
advertise_addr = "10.0.1.10:9100"   # 其他节点可访问的地址
raft_advertise_addr = "10.0.1.10:9200"

# 安全配置
shared_secret = "your-secret-key"
tls_enabled = true
tls_cert_file = "/etc/iedb/certs/cert.pem"
tls_key_file = "/etc/iedb/certs/key.pem"

[auth]
enabled = true
```

启动：

```bash
./iedb --config writer-01.toml
```

#### 第二步：添加 Reader 节点

```toml
# reader-01.toml
[license]
key = "IEDB-XXXX-XXXX-XXXX-XXXX"

[server]
port = 8000

[storage]
backend = "s3"
s3_bucket = "iedb-production"
s3_region = "us-east-1"

[cluster]
enabled = true
node_id = "reader-01"
role = "reader"
cluster_name = "production"
raft_bootstrap = false              # 非首个节点
seeds = "10.0.1.10:9100"            # Writer 的 coordinator 地址
raft_data_dir = "./data/raft"
coordinator_addr = ":9100"
raft_bind_addr = ":9200"
advertise_addr = "10.0.1.11:9100"
raft_advertise_addr = "10.0.1.11:9200"
shared_secret = "your-secret-key"

# 开启 WAL 复制以降低读取延迟
replication_enabled = true

[auth]
enabled = true
```

#### 第三步：添加 Compactor 节点

```toml
# compactor-01.toml
[license]
key = "IEDB-XXXX-XXXX-XXXX-XXXX"

[server]
port = 8000

[storage]
backend = "s3"
s3_bucket = "iedb-production"
s3_region = "us-east-1"

[cluster]
enabled = true
node_id = "compactor-01"
role = "compactor"
cluster_name = "production"
raft_bootstrap = false
seeds = "10.0.1.10:9100"
raft_data_dir = "./data/raft"
coordinator_addr = ":9100"
raft_bind_addr = ":9200"
advertise_addr = "10.0.1.12:9100"
shared_secret = "your-secret-key"

[compaction]
enabled = true
hourly_enabled = true
```

#### 第四步：启用高可用（添加 Standby Writer）

再部署一个 Writer 节点作为热备（`raft_bootstrap = false`）：

```toml
[cluster]
enabled = true
node_id = "writer-02"
role = "writer"
cluster_name = "production"
raft_bootstrap = false
seeds = "10.0.1.10:9100"

# 启用自动故障转移
failover_enabled = true
failover_timeout = 30
failover_cooldown = 60
```

#### 第五步：验证集群状态

```bash
# 查看集群概览
curl http://10.0.1.10:8000/api/v1/cluster

# 查看所有节点
curl http://10.0.1.10:8000/api/v1/cluster/nodes

# 查看健康状态
curl http://10.0.1.10:8000/api/v1/cluster/health
```

### 本地存储模式

在本地存储模式下，每个节点使用自己的本地磁盘。Writer 写入本地 Parquet 文件，通过 Raft 文件清单和节点间复制同步到 Reader。

```toml
[storage]
backend = "local"
local_path = "./data/iedb"

[cluster]
enabled = true
role = "writer"
# 开启文件复制
replication_enabled = true
```

> 本地存储模式需要 `shared_secret` 配置，用于节点间复制的安全认证。

## 请求路由

集群自动将客户端请求转发到合适的节点：

| 请求类型 | 路由策略 |
|---|---|
| 写入（MsgPack/LP/TLE） | → Primary Writer |
| 查询（SQL） | → Reader（轮询/最少连接/随机） |
| 管理类 API | → 本地处理，广播到集群 |

### 负载均衡策略

| 策略 | 说明 |
|---|---|
| `round_robin` | 轮询（默认） |
| `least_connections` | 最少连接数 |
| `random` | 随机选择 |

```toml
[cluster]
route_strategy = "least_connections"
route_timeout = 5000      # 转发超时（毫秒）
route_retries = 3         # 重试次数
```

**循环防护**：转发请求会携带 `X-iedb-Forwarded-By` 头标记，防止无限转发。

## WAL 复制

WAL（Write-Ahead Log）复制确保 Reader 节点能快速获取最新写入的数据，降低读取延迟。

```
Writer (Primary)
  │ WAL Entry
  ▼
[Replication Sender] ──► broadcast ──► [Replication Receiver] Reader-01
                      ──►  entries ──► [Replication Receiver] Reader-02
```

- Writer 将每个 WAL 条目广播到所有已连接的 Reader
- Reader 写入本地 WAL，然后应用到内存缓冲区（ArrowBuffer）
- Reader 定期向 Writer 发送 ACK 确认位点

```toml
[cluster]
replication_enabled = true
replication_lag_limit = 5000       # 最大复制延迟（毫秒）
replication_buffer_size = 10000    # 发送缓冲区大小
replication_ack_interval = 100     # ACK 间隔（毫秒）
```

## 自动故障转移

### Writer 故障转移

当 Primary Writer 不可用时，集群自动将 Standby Writer 提升为 Primary：

1. Raft Leader 定期检查 Primary Writer 健康（每 5 秒）
2. 连续 3 次失败 → 触发故障转移
3. 选择 Standby Writer（优先）或任意健康 Writer → 提升为 Primary
4. 冷却期 60 秒内不会重复切换

### Compactor 故障转移

- Leader 每 10 秒检查 Compactor 健康
- 不可用时，优先选择健康 `compactor` 节点，其次 `writer` 节点
- 新节点自动接管压缩调度器

### 配置

```toml
[cluster]
failover_enabled = true
failover_timeout = 30      # 故障转移超时（秒）
failover_cooldown = 60     # 冷却时间（秒）
```

## 运维指南

### 扩容 Reader

Reader 节点可以随时加入，无需重启现有节点：

1. 按照 Reader 配置模板准备新节点
2. 设置 `seeds` 指向任意现有 Writer 的 coordinator 地址
3. 启动新节点——自动加入集群并开始接收查询请求

### 缩容/移除节点

```bash
# 移除已死节点
curl -X DELETE http://writer:8000/api/v1/cluster/nodes/dead-node-id \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### 手动故障转移

```bash
# 触发 Writer 故障转移
curl -X POST http://writer:8000/api/v1/cluster/failover/writer \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### 查看 Raft 状态

```bash
curl http://writer:8000/api/v1/cluster | jq '.raft'
```

返回示例：

```json
{
  "enabled": true,
  "is_leader": true,
  "leader_addr": "10.0.1.10:9200",
  "leader_id": "writer-01",
  "state": "Leader",
  "stats": {
    "num_peers": "2",
    "applied_index": "15420",
    "last_snapshot_index": "10000"
  }
}
```

## 故障排除

**节点无法加入集群**：检查 `cluster.name` 是否一致，`shared_secret` 是否匹配，种子节点 coordinator 端口是否可达。

```bash
# 测试种子节点连通性
nc -zv 10.0.1.10 9100
```

**Raft 集群脑裂**：检查网络分区和选举超时配置。适当增加 `raft_election_timeout` 以应对高延迟网络。

**WAL 复制延迟过高**：减少 `replication_ack_interval`，或增加 Reader 节点带宽。

```bash
# 查看复制延迟指标
curl http://reader:8000/api/v1/metrics/replication
```
